# A 모델 카드 — 역·시간대·월 프로파일

모델 A@20261115-cbc66d8-rolling8-v1
저장소 커밋 cbc66d8 · 작성 2026-11-15 · 서빙 파일 `models/cal_A.joblib`

## 1. 목적

- 역할: T2(장기). 데이터 끝(2026-06-30) 이후 최대 366일 뒤까지의 장기 지평을 맡는다.
- 예측 대상: (호선, 역, 시간대) 한 조합의 승차 인원(명). 시간대는 하루 20구간이며 04~06시·06~07시 … 23~24시, 그리고 다음 날 00~04시 4시간을 묶은 24_01 구간으로 나뉜다.
- T1(단기)은 1~31일 지평을 뜻한다. A는 그 구간 성적도 산출되어 있으나 주 용도는 장기다.
- 알고리즘: `HistGradientBoostingRegressor` 하나(learning_rate 0.05, max_leaf_nodes 31, max_iter 300, random_state 42). A·B·C가 같은 알고리즘을 쓰고 입력 변수만 다르다. 세 모델의 차이가 알고리즘이 아니라 정보량에서만 나오게 하려는 설계다.

## 2. 정보집합

입력 변수 8개: `profile_month_mean` · `profile_n` · `profile_weekday_mean` · `profile_weekday_n` · `station_code` · `line_code` · `hour_code` · `weekday` (`models/metrics_calendar.json` features.A와 일치).

프로파일은 "그 역·시간대가 과거에 평균 몇 명 탔나"를 정답을 보지 않고 계산한 값이다.

as-of(기준 시점) 규칙 — `src/metro_insight/model/predictor.py` 동작 기준:

- 대상일이 2026-06-30 이후: `models/cal_profiles.npz`의 전체 이력(2024-01-08~2026-06-30) 프로파일을 그대로 쓴다. 미래 시점에는 그 날까지의 자료가 없으므로 고정값이며 as-of가 아니다.
- 대상일이 데이터 안: `models/boarding_history.npz`에서 대상일 **이전** 날짜 열만(`side="left"`, 그 날짜 열 제외) 고르고, 월 프로파일은 같은 달, 요일 프로파일은 같은 요일 행만 평균한다. 당일 값을 섞으면 성적이 실제보다 좋아지므로 구조적으로 배제한다.
- 해당 프로파일이 없으면 평균은 NaN, 관측 수는 0으로 두고 그대로 예측한다(학습과 같은 결측 규칙).
- 날씨는 입력에 없다. 기온·강수·적설은 A 계산에 쓰이지 않는다.
- 학습·평가 시점 규칙: train 행은 as-of, valid 행은 train_end(2025-10-01) 시점 고정, test 채점은 2026-02-14 시점 고정(`metrics_calendar.json` notes).
- 역 매칭: 지도 이름과 데이터 이름의 괄호 별칭을 붙여 찾는다('잠실(송파구청)'를 '잠실'로). 7호선 원본 '이수'는 지도 '총신대입구'로 연결한다(4호선 총신대입구 역 코드 116과 7호선 이수 239는 다른 역이라 섞지 않는다).

## 4. 실패 모드

- 공휴일: A의 입력에 공휴일 표시가 없다. A 단독 공휴일 슬라이스 성적은 출처에 없어 미산출로 남긴다. 현행 방식 기준선의 공휴일 MAE 159.9469는 비공휴일 90.1321의 약 1.8배로 측정되어 있다(`interval_decay_metrics.json` gates.calendar).
- 신규 역·데이터 없는 역: 지도는 420개 (호선, 역) 쌍을 갖지만 승차 이력이 있는 쌍은 273개다. 나머지 147개는 예측할 수 없고, 화면에는 "역은 학습 데이터에 없어 예측할 수 없습니다"가 나온다. 1호선은 102역 중 10역만 데이터가 있다.
- 음수 예측: 서빙 경로는 모델 출력을 자르지 않는다. 0으로 자르는 조치는 예측구간 실험에서만 적용했고(음수 72,806건이 0건이 됨) 서빙 동작이 아니다.
- 데이터 밖 기간: 2027-06-30 이후는 예측을 거부한다(데이터 끝 + 1년). 미래용 프로파일 파일이 없으면 예측 불가 안내가 나온다. 2026-12-29 이후는 Test 성적이 없어 ± 표시를 붙이지 않는다.
- 프로파일 결측: 그 달·그 요일에 관측이 0건이면 NaN 입력으로 계산한다. 성적이 나빠질 수 있으나 오류로 중단하지 않는다.

## 5. 금지 용도

- 역별 인력 배치, 안전 관리 인원, 열차 편성, 요금·정책 결정의 단정 근거로 쓰지 않는다. 예측은 참고값이다.
- 개별 예측 1건을 확정 수치로 제시하지 않는다. ±MAE는 그 날짜가 속한 지평 구간의 평균 오차이며 개별 예측의 오차 범위가 아니다.
- 정보집합이 다른 모델과 순위를 단정하지 않는다(A는 날씨·공휴일을 쓰지 않는다).

## 6. 갱신 주기

- 자동 재학습 스케줄은 저장소에 없다. 재학습은 `notebooks/train_calendar.py`를 사람이 실행한다(코드에 스케줄러·정기 실행 설정 없음).
- 데이터 갱신: 지하철 원본은 2026-06-30에서 끝나고, 2026년 7~12월 원본은 2027-01-29 공개 예정이다(`README.md` 데이터 파이프라인). 학습 데이터가 늘어나는 주기는 연 1회 수준이다.
- 날씨만 `notebooks/fetch_weather.py`로 매일 늘릴 수 있으나 A는 날씨를 쓰지 않으므로 A 성능에는 영향이 없다.
- 제안(근거 있는 확정 사항 아님): 지하철 원본 공개 이후 1회 재학습하고 `cal_profiles.npz`와 `boarding_history.npz`를 함께 다시 만든다. 프로파일 기준일(`predictor.DATA_END`)도 같은 커밋에서 갱신해야 한다.
