# 시간 감쇠 가중 분위수 실험 기록 (2026-11-15)

## 1. 목적과 가설

80% 예측구간의 포함률(실제 값이 구간 안에 들어온 비율, 이하 포함률)이 8개 기준 시점 전부에서
0.77~0.83 안에 들어오는지 확인한다.

3차 실행에서 원인은 잔차 분포 이동으로 좁혀졌다. 보정 분위수와 축척 정의는 뚜렷한 결함이
없었고(자기 포함률 지표는 순환 지표라 근거로 쓰지 않는다 — 4절), 실제 원인은 보정 창과 평가 창의
잔차 분포 불일치다. 같은 그룹에서 "보정 분위수 ÷ 평가 잔차의 0.8 분위수" 가 최대 3.13배까지 벌어졌다.

가설: 보정 창(90일) 안에서도 오래된 잔차가 최근보다 다른 수준을 담고 있다면, 잔차 나이에 따라
무게를 줄이면 창 편향이 줄어 포함률이 0.8 쪽으로 당겨진다. 반감기 30일이면 30일 전 잔차는 절반,
60일 전은 1/4, 90일 전은 1/8 무게가 된다.

## 2. 방법

- 가중치 w = 2^(−age/30). age = 평가 기준 시점 − 그 잔차가 발생한 날(일 단위). 나이는 행마다
  실제 날짜에서 계산하므로 보정 원점이 절단된 경우에도 어긋나지 않는다.
- 가중 분위수: 점수를 안정 정렬(mergesort)한 뒤 누적 가중 비율이 유한표본 수준
  ceil((n+1)·0.8)/n 을 처음 넘는 점수를 고른다. 같은 점수의 순서가 뒤집혀도, 입력 행 순서를
  섞어도 결과가 같다(결정론).
- 평가용 잔차 나이(일)는 0 이상이다. 나이가 음수(기준 시점 뒤 잔차)이거나 유한하지 않으면
  무게를 0 으로 둔다. 이번 실행의 기준 시점별 최소 나이는 8개 모두 0 이므로 아래 수치는 이
  방어 규칙을 넣어도 달라지지 않는다.
- 유지한 것: 그룹(지평밴드 4 × 규모 tertile 3 = 12개), 축척 정의(월 프로필 평균, 없으면
  (역, 시간대) 평균), 보정 원점 배치(창 90일), 유한표본 보정(근사 — 수준을 가중 유효표본이 아니라
  행 수 n 으로 계산한다. 아래 4절), 폴백 규칙, 게이트 정의, 밴드 0.77~0.83.
- 평가 행 집합은 3차와 동일하다. 기준 시점별 평가 행 수가 8개 모두 같고, 통합 6,983,340행도 같다.

## 4. 분위수 자체는 여전히 정상인지 (진단)

- 가중 분위수는 셔플에 결정론적이다. 점수·무게를 같은 순열로 섞어도, 같은 점수의 입력 순서가
  뒤집혀도 같은 값이 나온다(안정 정렬 + 누적 가중 역함수, `test_weighted_quantile_is_deterministic_...`).
- 정의가 명목 수준을 구현하는지는 표본 밖 기준으로만 확인할 수 있다. 합성 표준정규 표본
  (|N(0, 3)|, 40만 개)에서 가중 분위수는 해석적 0.8 분위수 3.8447 과 1% 안에서 맞는다
  (`tests/test_uncertainty.py::test_weighted_quantile_matches_analytic_quantile`).
- 같은 표본에 가중 포함률을 다시 재는 값(8개 기준 시점 전부 0.80001)은 근거로 쓰지 않는다.
  가중 분위수는 정의상 누적 가중 비율이 수준을 넘는 점수를 고르므로, 어떤 가중치를 넣어도
  포함률이 그 수준에 붙는다(무게를 뒤집어도 마찬가지). 순환 논증이라 분위수 구현의 근거가 못 된다.
- 원값 대조는 산출물로 했다. `calibrator.json` 의 그룹 분위수·축척과 `metrics.json` 의 포함률이
  같은 실행(`20261115-P3-R3-01`)의 같은 기준 시점에서 나온 값인지, manifest 해시가 두 파일과
  실제로 맞는지 확인했다(`notebooks/verify_manifest.py` 3/3 일치).
- 유한표본 보정은 근사다. 수준 ceil((n+1)·0.8)/n 을 가중 유효표본이 아니라 행 수 n 으로 계산하는데,
  무게가 기울면 유효표본(ESS = (Σw)²/Σw²)이 0.4n 수준까지 작아진다. 그만큼 수준이 조금 낮게 잡히나
  실측 포함률 영향은 1e-5 수준이라 판정을 바꾸지 않는다.
- 같은 표본을 **비가중** 포함률로 재면 0.7671~0.8055 로 흩어진다. 이는 가중 분위수가 무게가 큰
  최근 잔차 쪽에 맞춰졌기 때문이며, 남은 오차의 출처가 분위수 구현이 아니라 잔차 분포 이동임을
  보여 준다.

## 6. 채택 판정

**채택** — 기본 보정 경로를 시간 감쇠 가중 분위수로 바꾼다.

근거:
1. 밴드 안 통과 수가 3개 → 4개로 늘었다(목표는 8개, 미달 사실은 그대로).
2. 다른 게이트에 퇴행이 없다. 조건부 슬라이스 누락 0, 구간 교차 0, 음수 0, 달력 비교는 3차와
   같은 값·같은 판정, 분산 백테스트 실패 목록도 동일하다.
3. 구간 폭이 7/8 기준 시점에서 줄었고(합 1910.2 → 1868.7), 평균 편차도 줄었다.
4. 가중 분위수가 결정론적이고(셔플 불변) 합성 정규 표본에서 해석적 분위수와 1% 안에서 맞으므로,
   순서·수준 구현에서 온 오차가 아니다.

채택의 한계(숨기지 않음):
- 2025-02-13 은 0.8452 → 0.8535 로 악화됐다. 반감기 30일이 항상 유리하지는 않다는 뜻이다.
- 포함률이 0.83 을 넘는 기준 시점(2024-11-01·2024-12-15)은 여전히 폭이 과대하다. 이 두 기준 시점의
  평가 행은 전부 182-366 지평이고, 보정 원점이 데이터 시작(2024-01-08) 때문에 90일 학습분으로
  절단된다. 보정 모형과 평가 모형의 학습량 차이라는 구조 문제는 가중으로 해결되지 않는다.
- 따라서 이 실험은 "부분 개선" 이며 목표 달성이 아니다.

## 7. 손질한 결함

- 실행 로그를 열기 전에 이전 로그를 지우던 경로를 없앴다. 로그만 있는(중단된) 디렉터리에 다시
  돌면 `log-2.jsonl`, `log-3.jsonl` 처럼 비어 있는 이름을 골라 새로 쓴다. manifest 의 `log.path`
  에 실제 파일명을 적는다.
- 산출물도 같은 원칙으로 막았다. `metrics.json`·`calibrator.json`·`conditional_coverage.csv`·
  `manifest.json` 중 하나라도 있는 디렉터리로 다시 돌면 덮어쓰지 않고 멈춘다. 안내 문구에 다음
  가용 이름(`...-02`)을 적는다. 평가 프로토콜(`notebooks/eval_protocol.py`)이 run_id 충돌을
  거부하는 것과 같은 방향이다. 그래서 "이전 실행의 근거가 사라지지 않는다" 는 로그뿐 아니라
  산출물 전체에 해당한다.
- 재실행이 필요하면 새 디렉터리 이름을 쓴다(예: `--run-dir models\_exp\20261115-P3-R3-02`).
