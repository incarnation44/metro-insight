# 프로젝트 기획: 날씨·공휴일·과거 이용 패턴 기반 지하철 이용량 예측

> 실행 방법과 프로젝트 구조는 [README](../README.md)를 참고한다.

## 1. 프로젝트 개요

### 프로젝트명

**날씨·공휴일·과거 이용 패턴 기반 지하철 이용량 예측**

### 프로젝트 소개

본 프로젝트는 **과거 지하철 이용 패턴과 시간·요일·공휴일·날씨 정보를 활용하여 특정 역의 지하철 이용량을 예측하는 머신러닝 프로젝트**이다.

지하철 이용량은 단순히 시간대에 따라서만 달라지는 것이 아니라 평일·주말 여부, 공휴일, 날씨 등의 요인에 따라 변화할 수 있다.

따라서 여러 조건을 단계적으로 추가한 모델을 구성하고, 각 모델의 예측 성능을 비교하여 **어떤 정보가 지하철 이용량 예측에 실제로 도움이 되는지 분석**한다.

최종적으로는 사용자가 역과 날짜·시간을 선택하면 해당 조건의 예상 지하철 이용량을 보여주고, 예측된 이용량을 기반으로 **혼잡도를 직관적인 형태로 표시하는 서비스**를 구현하는 것을 목표로 한다.

---

## 2. 프로젝트 목표

### 2.1 지하철 이용량 예측

특정 역의 특정 시간대에 발생할 것으로 예상되는 지하철 이용량을 예측한다.

예를 들어 다음과 같은 조건이 주어졌을 때:

```text
역: 강남역
노선: 2호선
날짜: 2025-09-01
시간: 08시
요일: 월요일
공휴일: 아님
날씨: 맑음, 23℃
```

해당 조건에서 예상되는 지하철 이용량을 예측한다.

---

### 2.2 입력 데이터에 따른 모델 성능 비교

서로 다른 정보를 사용하는 3개의 모델을 구성하여 성능을 비교한다.

| 모델   | 사용 데이터                    | 목적                           |
| ---- | ------------------------- | ---------------------------- |
| A 모델 | 과거 이용 패턴                  | 과거 이용량만으로 어느 정도 예측할 수 있는지 확인 |
| B 모델 | 과거 이용 패턴 + 시간/요일/공휴일      | 시간 및 날짜 관련 정보가 예측에 미치는 영향 확인 |
| C 모델 | 과거 이용 패턴 + 시간/요일/공휴일 + 날씨 | 날씨 정보까지 추가했을 때의 성능 변화 확인     |

이를 통해 단순히 하나의 모델을 만드는 것이 아니라,

> **과거 이용 패턴 → 시간·요일·공휴일 → 날씨**

순으로 정보를 추가했을 때 예측 성능이 어떻게 변화하는지 분석한다.

---

### 2.3 실제 서비스 구현

분석 결과 가장 적절한 모델을 선정하고, 이를 실제 예측 기능에 적용한다.

서비스에서는 사용자가 역과 날짜·시간을 선택하면 해당 조건에 맞는 이용량을 예측하고, 예측된 이용량을 기반으로 혼잡 정도를 표시한다.

---

## 3. 데이터 구성

프로젝트에서는 크게 다음 데이터를 활용한다.

### 3.1 지하철 이용 데이터

지하철 역별·시간대별 이용량 데이터를 사용한다.

예상 주요 컬럼:

```text
date
line
station
hour
boarding
alighting
```

예시:

```text
date        line  station  hour  boarding  alighting
2025-09-01  2호선  강남역    08    12500      8300
```

* `date`: 이용 날짜
* `line`: 지하철 노선
* `station`: 역
* `hour`: 시간대
* `boarding`: 승차 인원
* `alighting`: 하차 인원

초기 모델에서는 **승차 인원(`boarding`)을 주요 예측 대상(Target)** 으로 사용하는 것을 기본으로 한다.

필요한 경우 하차 인원까지 확장할 수 있다.

---

### 3.2 시간 및 날짜 데이터

지하철 이용량의 시간적 패턴을 반영하기 위해 날짜에서 필요한 정보를 추출한다.

예상 Feature:

```text
year
month
day
weekday
hour
is_weekend
is_holiday
```

예를 들어:

```text
2025-09-01 08:00
→ 월요일
→ 평일
→ 공휴일 아님
→ 08시
```

와 같이 변환하여 모델의 입력으로 사용한다.

---

### 3.3 공휴일 데이터

공휴일 여부 및 공휴일과 관련된 정보를 활용한다.

예상 Feature:

```text
is_holiday
holiday_type
```

공휴일에는 일반적인 평일과 다른 이용 패턴이 나타날 수 있으므로 이를 모델에 반영한다.

---

### 3.4 날씨 데이터

날짜 및 시간에 따른 날씨 정보를 활용한다.

사용 가능한 데이터 범위에 따라 다음과 같은 변수를 고려한다.

```text
temperature
rainfall
precipitation
humidity
wind_speed
snowfall
```

모든 변수를 반드시 사용하는 것은 아니며, 실제 데이터 확보 이후 결측치, 상관관계 및 모델 성능 등을 확인하여 사용할 Feature를 결정한다.

---

## 4. 데이터 통합

서로 다른 출처의 데이터를 날짜와 시간 등의 기준으로 결합하여 하나의 학습 데이터셋을 구성한다.

최종적으로 다음과 같은 형태를 목표로 한다.

```text
date
line
station
hour
weekday
holiday
temperature
rainfall
boarding
```

예시:

```text
date        line  station  hour  weekday  holiday  temperature  rainfall  boarding
2025-09-01  2호선  강남역    08    월       0         23.1         0.0       12500
2025-09-01  2호선  강남역    09    월       0         24.0         0.0       11300
```

데이터를 결합할 때는 각 데이터의 날짜·시간 기준이 일치하는지 확인하고, 결측 데이터 및 데이터 형식 차이를 처리한다.

---

## 5. 머신러닝 데이터 구성

### 5.1 Feature와 Target

머신러닝에서는 각 행의 데이터를 이용하여 Target을 예측한다.

예를 들어 다음과 같은 데이터가 있다면:

```text
date        line  station  hour  weekday  holiday  temperature  rainfall  boarding
2025-09-01  2호선  강남역    08    월       0         23.1         0.0       12500
```

`boarding`을 예측 대상으로 설정할 경우:

```text
Feature
├── line
├── station
├── hour
├── weekday
├── holiday
├── temperature
└── rainfall

Target
└── boarding
```

즉, 여러 조건을 입력으로 사용하여 해당 시간의 승차 인원을 예측한다.

---

### 5.2 과거 이용 패턴 Feature

A 모델에서 사용하는 **과거 이용 패턴**은 단순히 현재 Target 값을 사용하는 것이 아니라, 예측 시점보다 이전에 존재하는 이용량 데이터를 Feature로 만든다.

예를 들어 다음과 같은 과거 이용량을 활용할 수 있다.

```text
previous_hour
previous_day
same_hour_previous_week
recent_average
```

예:

```text
현재 예측 시점: 2025-09-08 월요일 08시

2025-09-07 일요일 08시
2025-09-01 월요일 08시
최근 시간대 이용량
...
```

이처럼 **예측 시점보다 미래에 있는 데이터를 Feature로 사용하지 않도록 주의한다.**

이를 통해 미래 정보를 학습에 사용하는 **데이터 누수(Data Leakage)** 를 방지한다.

---

## 6. 모델 구성

### A 모델 — 과거 이용 패턴

```text
과거 이용 패턴
        ↓
    A 모델
        ↓
예상 이용량
```

과거 이용량에서 추출한 패턴을 중심으로 이용량을 예측한다.

기본적인 과거 패턴만으로 어느 정도의 예측 성능을 얻을 수 있는지 확인한다.

---

### B 모델 — 과거 이용 패턴 + 시간/요일/공휴일

```text
과거 이용 패턴
      +
시간 / 요일
      +
공휴일
      ↓
   B 모델
      ↓
예상 이용량
```

A 모델에 시간 및 날짜 관련 Feature를 추가한다.

이를 통해 단순한 과거 이용 패턴보다 시간·요일·공휴일 정보를 추가했을 때 성능이 얼마나 개선되는지 확인한다.

---

### C 모델 — 과거 이용 패턴 + 시간/요일/공휴일 + 날씨

```text
과거 이용 패턴
      +
시간 / 요일
      +
공휴일
      +
날씨
      ↓
   C 모델
      ↓
예상 이용량
```

B 모델에 날씨 정보를 추가한다.

최종적으로 C 모델을 실제 서비스의 기본 예측 모델로 사용하는 것을 목표로 한다.

---

## 7. 데이터 분할

지하철 이용량 데이터는 날짜와 시간에 따라 변화하는 **시계열(Time Series) 특성**을 가지고 있다.

따라서 일반적인 무작위 데이터 분할보다는 **시간 순서에 따른 분할**을 사용한다.

전체 데이터를 다음과 같이 구성한다.

```text
전체 데이터 100%

┌───────────────────────────────┐
│          Train 70%            │
├───────────────┬───────────────┤
│ Validation 15%│    Test 15%   │
└───────────────┴───────────────┘
        시간의 흐름 →
```

실제 데이터에서는 다음과 같이 **과거 → 미래 순서**로 분할한다.

```text
과거                                              미래
│                                                  │
▼                                                  ▼
┌──────────────────┬────────────┬────────────┐
│   Train 70%      │ Validation │   Test     │
│                  │    15%     │    15%     │
└──────────────────┴────────────┴────────────┘
```

### Train — 70%

모델이 패턴을 학습하는 데 사용하는 데이터이다.

```text
Train → 모델 학습
```

---

### Validation — 15%

학습된 모델의 성능을 확인하고 모델 또는 하이퍼파라미터를 선택하는 데 사용한다.

```text
Train
 ↓
모델 학습
 ↓
Validation
 ↓
모델 비교 및 조정
```

A/B/C 모델의 비교 및 모델 설정을 결정할 때 활용한다.

---

### Test — 15%

최종 모델의 성능을 평가하기 위한 데이터이다.

Test 데이터는 모델을 선택하거나 조정하는 과정에서 사용하지 않는다.

최종적으로 선택한 모델에 대해 한 번 평가하여 실제 일반화 성능을 확인한다.

```text
Train → 학습
Validation → 모델 선택/조정
Test → 최종 성능 평가
```

---

## 8. 평가 방법

모델의 예측값과 실제 이용량을 비교하여 모델의 성능을 평가한다.

주요 평가 지표로 다음을 사용한다.

### MAE

**Mean Absolute Error**

실제 값과 예측 값의 차이의 절대값 평균이다.

```text
MAE = 평균(|실제값 - 예측값|)
```

예를 들어 MAE가 500이라면 평균적으로 실제 이용량과 약 500명 정도 차이가 난다는 의미로 해석할 수 있다.

---

### RMSE

**Root Mean Squared Error**

예측 오차를 제곱한 후 평균을 구하고 다시 제곱근을 취한 값이다.

```text
RMSE = √(평균((실제값 - 예측값)²))
```

큰 오차에 더 큰 패널티가 적용되므로 큰 예측 오류가 발생하는 모델을 확인하는 데 유용하다.

---

## 9. 모델 분석 화면

서비스의 **예측하기 화면**에서는 모델을 단순히 A/B/C 탭으로 나누지 않고, 다음과 같이 **분석 모드와 실제 모드**로 구분한다.

### 분석 모드

A/B/C 모델의 예측 결과와 성능을 비교한다.

예:

```text
┌──────────────────────────────────────┐
│              분석 모드               │
├──────────────────────────────────────┤
│ 역       : 강남역                    │
│ 날짜     : 2025-09-01                │
│ 시간     : 08시                      │
├──────────────────────────────────────┤
│ A 모델 예상 이용량 : 11,850명        │
│ B 모델 예상 이용량 : 12,240명        │
│ C 모델 예상 이용량 : 12,500명        │
├──────────────────────────────────────┤
│ MAE                                    │
│ A : ...                               │
│ B : ...                               │
│ C : ...                               │
└──────────────────────────────────────┘
```

이를 통해 어떤 Feature를 추가했을 때 예측 성능이 개선되었는지 확인한다.

---

### 실제 모드

최종적으로 선택한 **C 모델**을 사용하여 이용량을 예측한다.

사용자는 역과 날짜·시간 등의 조건을 입력하고, 해당 조건의 예상 이용량과 혼잡 정도를 확인한다.

```text
┌──────────────────────────────────────┐
│              실제 모드               │
├──────────────────────────────────────┤
│ 역       : 강남역                    │
│ 날짜     : 2025-09-01                │
│ 시간     : 08시                      │
│ 날씨     : 맑음 / 23℃                │
├──────────────────────────────────────┤
│                                      │
│      예상 승차 인원                  │
│        12,500명                      │
│                                      │
│      예상 혼잡도                     │
│        혼잡                           │
│                                      │
└──────────────────────────────────────┘
```

## 11. 데이터 전처리

수집한 데이터를 머신러닝에 사용할 수 있는 형태로 변환한다.

주요 전처리 작업:

* 날짜 및 시간 형식 통일
* 지하철 노선명 통일
* 역명 통일
* 날짜에서 요일 추출
* 공휴일 여부 생성
* 날씨 데이터와 이용 데이터 결합
* 결측치 처리
* 이상치 확인
* 범주형 데이터 처리
* 수치형 데이터 전처리
* 과거 이용량 기반 Feature 생성

특히 데이터 결합 과정에서 동일한 날짜와 시간에 해당하는 데이터가 정확하게 매칭되는지 확인한다.

## 12. 데이터 누수 방지

본 프로젝트에서는 과거 이용 패턴을 Feature로 사용하기 때문에 **데이터 누수(Data Leakage)** 를 주의한다.

예측하려는 시점의 실제 이용량이나 미래의 이용량을 Feature로 사용하면 모델이 실제 상황에서는 알 수 없는 정보를 이용하게 된다.

따라서 원칙적으로:

```text
예측 시점
      │
      ▼
과거 데이터만 ──────→ Feature
      │
      X
미래 데이터 ────────→ 사용하지 않음
```

으로 구성한다.

또한 Test 데이터는 최종 평가 전까지 모델 학습이나 모델 선택에 사용하지 않는다.

---

## 13. 기대 결과

본 프로젝트를 통해 다음 내용을 확인하는 것을 목표로 한다.

1. 과거 지하철 이용 패턴만으로 어느 정도의 예측이 가능한가?
2. 시간·요일·공휴일 정보를 추가하면 예측 성능이 향상되는가?
3. 날씨 정보를 추가하면 예측 성능이 추가로 향상되는가?
4. A/B/C 모델 중 실제 서비스에 가장 적합한 모델은 무엇인가?
5. 예측된 이용량을 활용하여 사용자에게 직관적인 혼잡 정보를 제공할 수 있는가?

단순히 하나의 예측 모델을 만드는 것이 아니라, **Feature를 단계적으로 추가하면서 모델 성능이 어떻게 변화하는지를 분석하는 것**을 프로젝트의 주요 목표로 한다.

## 14. 프로젝트 진행 단계

### Step 1. 데이터 확보

* 지하철 이용 데이터 확보
* 날씨 데이터 확보
* 공휴일 데이터 확보
* 각 데이터의 기간 및 컬럼 확인

### Step 2. 데이터 전처리

* 날짜/시간 형식 통일
* 역 및 노선 정보 정리
* 결측치 처리
* 이상치 확인
* 데이터 병합

### Step 3. Feature Engineering

* 요일
* 주말 여부
* 공휴일 여부
* 시간대
* 과거 이용량
* 이동평균 등 과거 패턴 Feature
* 날씨 Feature

등을 생성한다.

### Step 4. 데이터 분할

```text
Train      70%
Validation 15%
Test       15%
```

시간 순서를 유지하여 분할한다.

### Step 5. 모델 학습

A/B/C 세 가지 모델을 구성하고 각각 학습한다.

### Step 6. 모델 평가

MAE, RMSE 등의 평가 지표를 이용하여 A/B/C 모델의 성능을 비교한다.

### Step 7. 분석 결과 시각화

* 실제 이용량 vs 예측 이용량
* 모델별 MAE
* 모델별 RMSE
* Feature 추가에 따른 성능 변화

등을 시각화한다.

### Step 8. 예측 서비스 구현

최종 모델을 이용하여 사용자가 선택한 역과 시간의 이용량을 예측한다.

### Step 9. 혼잡도 표시

예측된 이용량을 사용자가 이해하기 쉬운 혼잡 단계로 변환하여 표시한다.

## 15. 주의사항 및 한계

### 날씨 정보의 현실적인 사용

모델 학습과 성능 비교에는 과거 날짜의 **실제 관측 날씨**를 사용한다.

서비스에서는 미래의 날씨 예보 데이터를 사용하지 않고, 날씨 정보를 다음 두 가지 방식으로 입력한다.

| 구분 | 날씨 입력 방식 | 용도 |
| --- | --- | --- |
| 현재 날씨 | 날씨 API로 현재 관측 날씨 조회 | 현재 시점의 이용량 예측 |
| 날씨 선택 | 사용자가 날씨를 직접 선택 (맑음 / 흐림 / 비 등) | 특정 날씨 조건을 가정한 이용량 예측 |

```text
현재 시점 예측 → 날씨 API (현재 관측값)
조건 가정 예측 → 사용자 선택 날씨
```

따라서 날씨를 선택하여 예측한 결과는 **실제 미래 날씨를 반영한 예측이 아니라, 해당 날씨를 가정했을 때의 예상 이용량**이다.

또한 사용자가 선택하는 날씨는 범주형(맑음 / 흐림 / 비 등)이므로, 모델 입력과 일치시키는 방법이 필요하다.

* 학습 데이터의 관측값(강수량, 운량 등)으로 날씨 범주 Feature를 만들어 학습하거나
* 선택한 날씨 범주를 대표 수치(예: 비 → 일정 강수량)로 변환하여 입력한다.

현재 날씨 API의 응답 항목도 동일한 Feature 형태로 변환하여 사용한다.

---

### 혼잡도와 이용량의 차이

본 프로젝트에서 머신러닝 모델이 직접 예측하는 값은 기본적으로 **지하철 이용량**이다.

```text
모델
 ↓
예상 승차 인원
 ↓
혼잡도 계산/표시
```

따라서 **이용량 예측과 실제 차량 내부의 혼잡도는 동일한 개념이 아니다.**

정확한 혼잡도를 산출하려면 승차 인원뿐만 아니라 열차 수송량, 하차 인원, 시간대별 승객 분포 등의 추가 정보가 필요할 수 있다.

본 프로젝트에서는 우선 예측된 이용량을 기반으로 한 **상대적인 혼잡 수준**을 제공하는 것을 목표로 한다.

---

## 16. 최종 목표

본 프로젝트의 최종 목표는 다음과 같다.

> **과거 지하철 이용 패턴에 시간·요일·공휴일·날씨 정보를 결합하여 특정 역의 이용량을 예측하고, 각 Feature의 추가가 예측 성능에 미치는 영향을 분석한 뒤 이를 실제 예측 서비스로 구현한다.**

최종적으로 사용자가 지하철 역과 날짜·시간을 선택하면 해당 조건의 예상 이용량을 확인하고, 이를 바탕으로 현재 또는 특정 시간대의 혼잡 수준을 직관적으로 파악할 수 있도록 한다.
